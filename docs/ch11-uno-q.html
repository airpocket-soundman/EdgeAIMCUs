第11章

Arduino UNO Q（STM32U585 ＋ QRB2210）

おなじみの Arduino の形に、マイコンと Linux コンピュータが同居。「二刀流」でエッジAIを楽しみます。

ボード紹介

Arduino UNO Q は、見た目はおなじみの Arduino UNO。でも中身はまったくの別物です。1枚の基板に、

  • マイコン：ST の STM32U585（Cortex-M33）
  • Linux が動くプロセッサ：Qualcomm の QRB2210（Cortex-A53 ×4）

の2つが載っていて、おたがいに Bridge という仕組みで会話できます。4章の「グループD：二刀流タイプ」です。

マイコン側Linux 側
チップSTM32U585Qualcomm QRB2210
コアCortex-M33、160MHzCortex-A53 ×4、2.0GHz ＋ GPU
メモリSRAM 786KB、Flash 2MBRAM 2GB または 4GB
得意なことセンサーを正確なタイミングで読む、モーター制御重い計算、Python、Web画面、音声合成
プログラムArduino スケッチ（Zephyr ベース）Python（Debian Linux）

開発は Arduino App Lab で、マイコン側のスケッチと Linux 側の Python を1つの「アプリ」としてまとめて扱えます。

二刀流の使い分け

作者の UNO Q の作品は、どれも同じ役割分担になっています。

Linux は便利ですが、「ぴったり 39マイクロ秒ごとにセンサーを読む」ような仕事は苦手です。逆にマイコンは、大きなモデルやたくさんのデータを扱うのが苦手。それぞれの得意なことだけをやらせるのが、二刀流ボードのいちばんおいしい使い方です。

ちょっと寄り道：これもエッジAI？

UNO Q の作品では、AIの推論は Linux 側で動いています。「それってマイコンでAIを動かしてるの？」と聞かれると、正確には「ちがう」。でも、センサーのすぐそばの1枚の基板の上で、ネットにつながずにAIが答えを出しているという意味では、立派なエッジAIです。この本では、マイコンと組み合わせて使うこうしたボードも仲間として紹介していきます。

実例：やまびこ1号 ― 音だけを頼りに位置を当てる（chikuwa-flute-robot）

人の口笛を聞いて、それをスライドホイッスルで吹き返すロボット、やまびこ1号。聞いた音を返すから「やまびこ」です。

この作品のすごいところは、演奏そのものより位置センサーを1つも使っていないことです。

音の高さを「ものさし」にする

スライドホイッスルは、筒の中のピストンを動かすと音の高さが変わる楽器です。ふつうのロボットなら、ピストンの位置をエンコーダー（位置センサー）で測って制御します。やまびこ1号は、そのセンサーをつけません。かわりに、

鳴っている音の高さ ＝ いまピストンがいる場所

として、マイクの音だけを位置のものさしにするのです。

ロマンのあるアイデアですが、このものさし、センサーとしてはかなりの困りもの。

ふつうのエンコーダー音のものさし
遅れほぼゼロ10〜50ミリ秒。しかも個体ごとに違う
測れないときなし鳴っていない間はまったく無信号
まちがいなしオクターブを間違えると、位置が2倍ずれる
余計な影響なし気温（約3セント/℃）、送風の圧力
目盛りまっすぐ曲がっている（音の高さは管の長さの逆数）

この5つを同時に相手にする「位置の推定係」を人の手で書くのは、かなり大変です。だからAIの出番。ここでのAIの役割は、ロボットを動かす制御器ではなく、いまどこにいるかを当てる観測器です。

ちょっと寄り道：セントって？

音の高さのずれを表す単位です。半音が100セント、1オクターブが1200セント。人が「音痴だな」と感じ始めるのが、だいたい20〜30セントのずれだと言われます。この節に出てくる数字は、すべてこの単位です。

「吹くほど慣れてくる」を、記憶だけでやる

さらにおもしろいのが、学習のさせ方です。笛は個体ごとに、モーターの速さも管の長さも微妙に違います。ふつうなら、機体ごとの数値を測って設定ファイルに書いておきます。やまびこ1号は、それをしません。

  • 校正の手順も、設定ファイルも持たない
  • 機体のクセは、AIモデル（GRU：記憶を持つ小さなニューラルネットワーク）の記憶の中だけに持つ
  • 記憶を消すのは電源を入れたときだけ。曲をまたいで持ち越す
  • 起動直後は下手で、何曲か吹くうちに合ってくる

シミュレーター上で200台ぶんの笛を用意して比べた結果がこちらです（実際に鳴った音程のずれ、単位はセント。小さいほど上手）。

位置の当て方1曲目2曲目3曲目4曲目5曲目
音を聞かない（推測だけ）221208239241212
位置センサーをつける7573757373
音で直す（記憶なし）29.928.329.832.028.4
音で直す＋AIの記憶（GRU）26.219.319.419.518.2
同じAIから記憶だけ消したもの26.225.126.527.125.1

読みどころが2つあります。

  • 音のものさしは、位置センサーより正確だった（30セント 対 75セント）。位置センサーは「ピストンがどこにいるか」は正確に知っていても、「その笛では、その位置で何の音が鳴るか」を知りません。音で聞けば、そこが一発でわかります。
  • 記憶があると、吹くほど上手くなる。まったく同じAIから記憶だけを消すと（いちばん下の行）、何曲吹いても1曲目と同じ下手さのまま。差は記憶だけです。

極めつけは、演奏の途中で笛を別の個体に付け替えたとき。AIには何も知らせません。それでも、

位置の当て方2曲目3曲目（付け替え直後）4曲目5曲目
機体のクセを外部に記録する方式22.037.238.132.0
AIの記憶（GRU）19.332.420.818.6

AIのほうは1曲で立ち直り、外部に記録する方式は古い記憶を引きずったままです。「いつ古い記憶を捨てるか」まで、学習で決まったということ。ちょっと感動しませんか？

UNO Q での役割分担

  • QRB2210（Linux 側）：口笛の音程を解析し、AIが位置を推定して、10ミリ秒ごとにモーターの指示を出す。シミュレーターと学習のコードは numpy だけで書かれていて、そのまま UNO Q の Linux 側で動かせます（学習そのものはGPU付きのPCで実施）。
  • STM32U585（マイコン側）：I2S マイク（ICS-43434）の音を SAI で取り込み、モーターとバルブを正確なタイミングで動かす。

「分類して終わり」ではなく、AIが現実世界を相手に、リアルタイムで手を動かす。これもエッジAIの、とびきり楽しい遊び方です。
