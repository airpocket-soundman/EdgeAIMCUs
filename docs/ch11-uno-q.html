第11章

Arduino UNO Q（STM32U585 ＋ QRB2210）

おなじみの Arduino の形に、マイコンと Linux コンピュータが同居。「二刀流」でエッジAIを楽しみます。

ボード紹介

Arduino UNO Q は、見た目はおなじみの Arduino UNO。でも中身はまったくの別物です。1枚の基板に、

  • マイコン：ST の STM32U585（Cortex-M33）
  • Linux が動くプロセッサ：Qualcomm の QRB2210（Cortex-A53 ×4）

の2つが載っていて、おたがいに Bridge という仕組みで会話できます。4章の「グループD：二刀流タイプ」です。

マイコン側Linux 側
チップSTM32U585Qualcomm QRB2210
コアCortex-M33、160MHzCortex-A53 ×4、2.0GHz ＋ GPU
メモリSRAM 786KB、Flash 2MBRAM 2GB または 4GB
得意なことセンサーを正確なタイミングで読む、モーター制御重い計算、Python、Web画面、音声合成
プログラムArduino スケッチ（Zephyr ベース）Python（Debian Linux）

開発は Arduino App Lab で、マイコン側のスケッチと Linux 側の Python を1つの「アプリ」としてまとめて扱えます。

二刀流の使い分け

作者の UNO Q の作品は、どれも同じ役割分担になっています。

Linux は便利ですが、「ぴったり 39マイクロ秒ごとにセンサーを読む」ような仕事は苦手です。逆にマイコンは、大きなモデルやたくさんのデータを扱うのが苦手。それぞれの得意なことだけをやらせるのが、二刀流ボードのいちばんおいしい使い方です。

ちょっと寄り道：これもエッジAI？

UNO Q の作品では、AIの推論は Linux 側で動いています。「それってマイコンでAIを動かしてるの？」と聞かれると、正確には「ちがう」。でも、センサーのすぐそばの1枚の基板の上で、ネットにつながずにAIが答えを出しているという意味では、立派なエッジAIです。この本では、マイコンと組み合わせて使うこうしたボードも仲間として紹介していきます。

実例1：IchiPing を UNO Q へ（IchiPing-UNO-Q）

8章の IchiPing（音で窓の開け閉めを当てる）の UNO Q 版です。

  • STM32U585：スピーカーとマイクの入出力をリアルタイムで担当
  • QRB2210：音の処理と、1次元 CNN による推論を担当

おもしろいのは、MCX N947 で100%だったモデルを UNO Q の上でそのまま使うと、正解率が20.8%まで落ちたことです。マイクやスピーカー、置き場所が変わると、「響き」の聞こえ方も変わってしまうんですね。

そこで、UNO Q の実機でデータを録りなおし、さらに温度変化で音の高さがわずかにずれることを見こして、周波数を少しだけ伸び縮みさせたデータで水増し（データ拡張）しました。その結果、

条件32状態14グループ
安定した状態（朝9時）91.7%100%
温度変化で音の高さがずれた状態74.7〜81.9%100%
人の話し声が流れている状態81.9%100%

まで回復しました。14グループの判定は、どの条件でも100%を保っています。「機械が変われば、AIも学び直し」。エッジAIを別のボードに引っ越すときの、大事な教訓です。

リポジトリ：airpocket-soundman/IchiPing-UNO-Q

実例2：アクリル板の楽器を UNO Q へ（acrylic_pan_uno_q）

9章のアクリル板の楽器を、UNO Q で作りなおしたものです。

  • STM32U585：加速度センサー（KX134）を SPI で 1秒に25,600回 読み、たたいた瞬間に 512サンプルを切り出す
  • QRB2210：特徴量を計算して、128-32-12 のモデルで12エリアを推論。Web画面を表示し、FluidSynth で音を鳴らす

Solist-AI では「16KB に収める」ことが最大のテーマでしたが、UNO Q の Linux 側ならメモリはたっぷり。画面や音の演出にも力を入れられます。同じ作品でも、マイコンの性格が変わるとがんばりどころが変わるのがおもしろいところです。

リポジトリ：airpocket-soundman/acrylic_pan_uno_q

実例3：口笛をまねる、ちくわ笛ロボット（chikuwa-flute-robot）

ちくわで作った笛を、ロボットが吹く。しかも、人の口笛の音程をまねして吹く。そんなロボットのための強化学習の環境です。

  • 笛の中のピストン（プランジャー）の位置を、モーターで動かして音程を変えます。
  • 位置センサーのかわりに、笛の音程そのものを位置の手がかりにする、というアイデアで制御します。
  • シミュレーターと学習スクリプトは numpy だけで書かれていて、UNO Q の Linux 側でそのまま動かせるようにしています。
  • マイコン側では、I2S マイク（ICS-43434）の音を STM32U585 の SAI で取り込む実験を進めています。

「分類」だけでなく、「うまく吹けたらごほうび」で上達していく強化学習も、エッジAIの楽しい遊び方のひとつです。

リポジトリ：airpocket-soundman/chikuwa-flute-robot
